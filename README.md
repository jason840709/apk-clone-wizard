# APK 分身精靈

在 Mac 上把 Android 安裝檔製作成可同時安裝的分身。每個分身可以自訂名稱，保留各自的設定與資料；原 App 更新後，可以沿用同一編號製作更新檔。

## 開始使用

下載最新 Release 的工具壓縮檔，解壓縮後雙擊圖形啟動入口（完整檔名見附錄）。把安裝檔拖入視窗，設定起始編號與數量，再按「製作分身」。例如起始編號 1、數量 5，就是製作第 1 到第 5 個分身。

名稱欄每行對應一個分身。整欄留空會沿用上次名稱；某個編號第一次製作時，使用原名加編號。開始填寫時，每個編號都要填一行，不能用空白行跳過。

需要 Python 3.10 以上、JDK、Apktool、Android Build Tools；圖形視窗另需 Apple Command Line Tools。已有工具可依附錄填入設定，不必重裝。尚未準備環境時，專案附有環境安裝入口（完整檔名見附錄）：會在工具資料夾下載固定版本並核對雜湊，Android 工具安裝前會顯示授權條款。請依自己電腦的環境管理規則決定是否使用。

## 更新分身

下次拖入同一個原始 App 的新版，選相同編號，並保留原私密金鑰。工具會保存每個編號的套件識別、簽章身分、顯示名稱與版本代碼；改名稱時，套件識別不變。版本代碼會高於輸入檔及本機保存或匯入的紀錄。工具不會讀取手機目前的安裝版本。

只想更新第二個分身，填「起始編號 2、數量 1」。其他編號的紀錄會保留。圖形視窗與終端問答入口現在使用同一套更新流程。

「沿用上次分身設定」可選完整舊輸出資料夾，或保存的設定檔。完整舊輸出會額外核對其中安裝檔的實際簽章和內容；獨立設定檔則核對格式及本機金鑰。載入舊紀錄不會覆蓋較新的版本進度或丟掉其他編號。

原金鑰遺失，或與已有設定不符時，工具會停止。安裝檔只能用來核對簽章，無法取回私密金鑰；新的金鑰不能用來更新另一個簽章製作的舊分身。請一起保留簽章資料夾與分身設定，不要把它們當快取刪掉或上傳公開網站。

## 驗證範圍

Android 10 模擬器已驗證兩個分身從舊版覆蓋更新到新版、更新時改名，以及單獨更新第 2 個分身；各自的偏好和私有測試檔都保留。22 項單元測試另涵蓋舊紀錄合併、版本遞增、名稱字元、金鑰不符及取消時的資料一致性。

這些是合成資料的測試結果。其他 App 可能另有簽章、服務或原生套件限制，完成製作仍需確認實際功能。

## 附錄：檔案與開發

- 圖形入口：`啟動APK分身精靈.command`；環境安裝入口：`安裝本機環境.command`。

- `06-精靈私有簽章/` 保存私密金鑰與密碼；`07-分身設定/` 保存更新對應。兩者都不包含在下載包中，使用後須自行妥善保留。
- `03-精靈快取/` 保存可重建的原生視窗；Swift 編譯的模組鎖及連結暫存限本機 APFS/HFS，完成後普通複製成品，不使用 NTFS 硬連結鎖流程。
- `tools.example.json` 可複製為 `tools.local.json`，填既有 SDK、JDK、Apktool 位置；也支援 `ANDROID_SDK_ROOT`、`APKTOOL_PATH`。啟動器先載入本工具的便攜環境，再找現有 Python，可用 `WIZARD_PYTHON` 指定解譯器。
- `啟動終端分身精靈.command` 是同一後端的問答入口。直接呼叫低階引擎 `apk_clone_maker.py` 不會代管圖形版更新設定。
- `python3 -B -m unittest test_bridge test_profiles` 執行更新流程測試；`--self-test` 檢查拖入判斷邏輯，並不等同 Finder 實際拖放。
